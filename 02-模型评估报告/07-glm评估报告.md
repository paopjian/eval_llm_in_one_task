## 💻 代码实现分析

### 核心技术实现

#### 1. Histogram方法 ✅

```python
# 2,000,000 bins，bin宽 1e-6
bins=2_000_000
```

**特点**:
- **超高分辨率**: 2,000,000 bins (最高)
- 分辨率: 0.000001
- 内存占用: O(bins) ≈ 16MB

#### 2. FP32精确计算（关闭TF32）⚡

```python
torch.backends.cuda.matmul.allow_tf32 = False
# fp32 精确计算，关闭 TF32
```

**特点**:
- ✅ **显式关闭TF32**
- ✅ 保证FP32精度
- ⚠️ 牺牲了性能换取精度

#### 3. 多卡并行 + 动态任务队列 ✅

```python
# tile 任务队列动态分配（天然负载均衡）
# 每 GPU 一个进程，spawn模式
ctx = mp.get_context('spawn')
```

**特点**:
- **动态任务队列**: 类似参考实现
- Spawn模式: 独立进程
- 宽tile优先入队

#### 4. 共享内存张量 ✅

```python
# 共享内存张量，避免向每个 worker 复制特征
feats_shm = torch.from_numpy(feats).share_memory_()
ids_shm = torch.from_numpy(ids_cont).share_memory_()
```

**特点**:
- ✅ 避免特征复制
- ✅ 内存效率高
- ✅ 启动速度快

#### 5. 提取模式：二次扫描 ✅

```python
# 第一遍: 统计直方图 + 精确正样本
# 第二遍: 提取 above/below 阈值样本对
```

**特点**:
- ✅ 两遍扫描分离
- ✅ 代码清晰
- ⚠️ 需要额外时间（如启用）

#### 6. 区块大小优化 ⚡

```python
# block=16384 (vs 参考的10240)
# 更大的block，减少kernel启动次数
```

## 💡 核心发现

### 1. 超高精度直方图 🏆

**GLM的选择**:
```python
bins=2_000_000  # 2M bins，分辨率1e-6
```

| 模型 | Bins | 分辨率 | 内存 |
|------|------|--------|------|
| **GLM** | **2M** ⚡⚡ | **1e-6** ⚡⚡ | ~16MB |
| Codex-sol-2 | 200K | 1e-5 | ~1.6MB |
| DeepSeek | 200K | 1e-5 | ~1.6MB |
| Grok | 100K | 2e-5 | ~800KB |
| Gemini | 100K | 2e-5 | ~800KB |
| Claude | 2K | 1e-3 | ~16KB |
| 参考v5 | 20M (可配) | 1e-7 | ~160MB |

**GLM的优势**:
- ✅ 阈值精度最高（除参考外）
- ✅ 适合科研和验证
- ⚠️ 内存占用稍高（16MB vs 1.6MB）

### 2. 共享内存优化

**GLM的实现**:
```python
feats_shm = torch.from_numpy(feats).share_memory_()
ids_shm = torch.from_numpy(ids_cont).share_memory_()
```

**优势**:
- ✅ 避免特征复制到每个worker
- ✅ 节省内存（7×400MB = 2.8GB）
- ✅ 加快启动速度

**对比**:
| 模型 | 共享内存 | 特征复制 |
|------|---------|---------|
| **GLM** | ✅ ⚡ | 0次 |
| **Codex-sol-2** | ✅ | Fork自动 |
| Grok | ❌ | 7次 |
| DeepSeek | ❌ | 7次 |
| Gemini | ❌ | 7次 |

### 3. 精度 vs 性能的权衡

**GLM的选择**:
- 显式关闭TF32
- 2M bins超高精度
- 优先精度而非性能

**性能影响**:
```
当前FP32: 5.3秒
如使用TF32: 估计4.3-4.5秒
差距: 约1秒 (20%)
```

### 4. Spawn vs 线程池

**GLM使用Spawn**:
- 进程启动开销: 约1-2秒
- 稳定性好
- 代码简单

**Grok使用线程池**:
- 无启动开销
- 性能最优
- 需注意CUDA上下文

**性能差距**:
```
GLM (spawn): 5.3秒
如用线程池: 估计3.5-4.0秒
潜在提升: 1.3-1.8秒
```
