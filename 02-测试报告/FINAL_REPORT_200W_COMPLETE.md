## 失败模型详细分析

### 1. GLM-Pro - 系统内存爆满 ❌

**问题**: 代码设计缺陷，系统内存在1分钟内从10GB暴增到158GB

```
GPU状态（正常）：
- 7卡利用率：99-100%
- 显存占用：7.7GB/卡

系统内存（异常）：
- 0秒：10GB
- 30秒：28GB (+18GB)
- 60秒：158GB (+130GB，持续暴增）
- 导致SSH断连
```

**尝试过的优化**:
- ❌ 块大小从8192×65536减半到4096×32768 → GPU显存正常但系统内存仍爆满

**结论**: 非参数问题，需重写内存管理逻辑

---

### 2. DeepSeek-Pro - 系统内存爆满 ❌

**问题**: 与GLM-Pro完全相同的内存泄漏问题

```
系统内存增长：
- 0秒：10GB
- 30秒：28GB (+18GB)
- 60秒：158GB (+130GB)
```

**尝试过的优化**:
- ❌ 块大小从16384减半到8192 → GPU显存正常但系统内存仍爆满

**结论**: 代码设计缺陷，无法完成200万数据评估

---

### 3. Codex-Sol-M - 并行失败 ❌

**问题**: multiprocessing只有1个GPU在工作，其余6个闲置

```
进程状态：
- 7个GPU进程都启动，各占8GB显存
- 但只有1个进程在工作（CPU 100%）
- GPU利用率0-9%
- 运行11分钟仍未完成
```

**对比**:
- ✅ Codex-Sol: 122秒成功
- ✅ Codex-Sol-2: 52秒成功
- ❌ Codex-Sol-M: 并行实现有缺陷

**结论**: multiprocessing的spawn模式在7卡并行时有问题

---

### 4. Claude-Opus - 文件系统问题 ❌

**问题**: 临时文件管理失败，导致内存爆满

```
错误信息:
FileNotFoundError: [Errno 2] No such file or directory: '/tmp/tmpjsalrq9h/gpu_0.pkl'

内存增长：
- 计算过程中系统内存持续暴增
- 最终导致SSH断连（与GLM-Pro/DeepSeek-Pro相同）
```

**结论**: 代码实现问题，临时文件管理失败 + 系统内存泄漏

---

### 5. DeepSeek - 数据一致性检查失败 ❌

**问题**: 启动后立即失败，运行仅9秒

```
错误信息:
AssertionError: 直方图计数不一致!

现象:
- 进程启动后9秒即失败
- 没有进入计算阶段
- 可能是数据加载或初始化阶段的校验失败
```

**结论**: 数据格式兼容性问题或内部一致性检查过于严格

## 问题模型修复建议

### GLM-Pro, DeepSeek-Pro, Claude-Opus（系统内存爆满）

**可能原因**:
1. 结果累积方式错误（不断append大数组到Python list）
2. 中间Tensor未及时释放，Python对象引用计数问题
3. 使用了不当的数据结构导致内存副本爆炸

**修复方向**:
1. 使用流式处理，不累积全部结果在内存
2. 及时释放中间Tensor：`del tensor; torch.cuda.empty_cache()`
3. 使用内存映射文件或磁盘存储中间结果
4. 检查是否有大数组的深拷贝操作

### Codex-Sol-M（并行失败）

**可能原因**:
1. multiprocessing.Queue初始化或通信问题
2. spawn模式的上下文传递失败
3. 任务分配逻辑错误

**修复方向**:
1. 检查multiprocessing.Queue的使用方式
2. 改用torch.multiprocessing
3. 参考Codex-Sol-2的成功实现

### DeepSeek（数据一致性检查失败）

**可能原因**:
1. 数据格式不兼容
2. 内部断言条件过于严格
3. 初始化阶段的校验逻辑有问题

**修复方向**:
1. 检查数据加载逻辑
2. 放宽或修正一致性检查条件
3. 添加详细的错误日志

## 结论

### 核心发现

1. **6个模型成功**完成200万数据集评估，性能从47秒到796秒
2. **5个模型失败**，都是代码实现问题：
   - 3个: 系统内存泄漏（GLM-Pro, DeepSeek-Pro, Claude-Opus）
   - 1个: 并行实现缺陷（Codex-Sol-M）
   - 1个: 数据兼容性问题（DeepSeek）
3. **GPU显存不是瓶颈**，所有失败都是系统内存或代码逻辑问题
4. **参数调优无法解决**失败的模型，需要修改代码实现

### 生产环境推荐

1. **速度优先**: GLM (47秒)
2. **稳定性优先**: Codex-Sol-2 (52秒)
3. **吞吐量优先**: Gemini (145秒, 37.758 Giga-Pairs/s)
4. **完整性优先**: Qwen (796秒, 最完整的TPIR@FPIR指标)

### 最佳选择

**Codex-Sol-2** 或 **GLM** 是生产环境的最佳选择：
- 速度快（47-52秒）
