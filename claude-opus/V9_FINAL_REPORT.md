## 二、三大核心优化

### 1. 动态任务池 - 解决负载不均衡

**问题诊断**:
```
v8版本按行分配：
GPU 0: 处理行 0-29033    → 50亿对，耗时66秒 ⬅️ 最慢
GPU 6: 处理行 174198-end → 4.2亿对，耗时5.6秒 ⬅️ 最快
负载差距: 12倍！
```

**原因分析**:
- 上三角矩阵：前面的行要计算更多列
- GPU0要算29033×(203234-29033) = 50亿对
- GPU6只算29036×29036/2 = 4.2亿对

**优化方案**:
```python
# 创建任务池：将矩阵分成2048×2048的小块
tasks = []
for i in range(0, N, 2048):
    for j in range(i_end, N, 2048):
        tasks.append((i, i_end, j, j_end))
# 共4950个任务块

# 动态分配：每个GPU完成一块后立即取下一块
while True:
    task = task_queue.get()
    if task is None: break
    # 处理任务...
```

**效果**:
```
v9版本动态分配：
GPU 0: 670个任务, 25.40秒
GPU 1: 675个任务, 25.01秒
GPU 2: 766个任务, 25.01秒
GPU 3: 681个任务, 25.01秒
GPU 4: 696个任务, 24.96秒
GPU 5: 815个任务, 24.93秒
GPU 6: 647个任务, 24.71秒

负载均衡度: 97.3% (最快24.71s vs 最慢25.40s)
```

**提升**: 从12%到97%，负载差距从12倍缩小到1.03倍！

## 六、技术洞察

### 1. 上三角矩阵的负载不均衡陷阱

**问题本质**:
```
按行分配看似公平：
GPU0: 行 0-29033     (29033行)
GPU1: 行 29033-58066 (29033行)
...

但计算量差异巨大：
GPU0: 29033 × 174201 = 50亿对
GPU1: 29033 × 145168 = 42亿对
...
GPU6: 29036 × 14518  = 4.2亿对 ⬅️ 只有GPU0的1/12！
```

**解决方案**: 
- 将矩阵分成小块（2048×2048）
- 用任务队列动态分配
- 快的GPU自动多干活

### 2. FP16的性价比

**优势**:
- Tensor Core加速：2-3倍
- 显存减半：更大batch
- 带宽加倍：数据传输快

**劣势**:
- 精度损失：通常<1%
- 需要转换：FP16→FP32

**结论**: 对于相似度计算，FP16完全够用！

### 3. 直方图的威力

**传统方法**:
```python
# 存储206亿个float32值
neg_sims = np.zeros(20_649_748_677, dtype=np.float32)
# 内存: 82GB
```

**直方图方法**:
```python
# 只存储2000个bin的计数
neg_hist = np.zeros(2000, dtype=np.int64)
# 内存: 31KB
```

**核心思想**: 
- TPIR@FPIR只需要分布特征，不需要每个值
- 用统计代替存储
- 精度损失极小（0.0005）

## 八、代码关键片段

### 1. 动态任务池
```python
def create_task_pool(N, block_size=2048):
    tasks = []
    for i in range(0, N, block_size):
        i_end = min(i + block_size, N)
        for j in range(i_end, N, block_size):  # 只处理上三角
            j_end = min(j + block_size, N)
            tasks.append((i, i_end, j, j_end))
    return tasks
```
