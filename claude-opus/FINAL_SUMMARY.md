## 三、核心技术突破

### 突破1：直方图统计（v8）

**问题诊断**：
```
v7版本需要存储所有相似度值：
- 正样本：2,179,084个 → 8.3MB
- 负样本：20,649,748,677个 → 82GB
- 多卡传输：82GB × 7 = 574GB
```

**优化思路**：
```
用户提示："你真的需要保存每一个相似度值吗？
能否用统计分布代替全量数据？"

核心洞察：TPIR@FPIR只需要分布特征，不需要每个值
```

**解决方案**：
```python
# 传统方法：存储所有值
neg_sims = []  # 206亿个float32 → 82GB

# 直方图方法：只存储分布
neg_hist = np.zeros(2000, dtype=np.int64)  # 2000个计数 → 31KB

# 相似度值 → bin索引
bin_idx = int(sim_value * 2000)
neg_hist[bin_idx] += 1
```

**效果**：
- 内存：82GB → 31KB（**260万倍**）
- 传输：574GB → 217KB
- 合并：1800秒 → 0.001秒

### 突破2：动态任务池（v9）

**问题诊断**：
```
v8按行分配任务，负载严重不均：
GPU 0: 处理行 0-29k        → 50亿对 → 66秒 ⬅️ 最慢
GPU 1: 处理行 29k-58k      → 42亿对 → 53秒
GPU 2: 处理行 58k-87k      → 35亿对 → 46秒
GPU 3: 处理行 87k-116k     → 27亿对 → 37秒
GPU 4: 处理行 116k-145k    → 20亿对 → 28秒
GPU 5: 处理行 145k-174k    → 13亿对 → 18秒
GPU 6: 处理行 174k-203k    → 4.2亿对 → 5.6秒 ⬅️ 最快

负载差距：12倍！
```

**根本原因**：
```
上三角矩阵特性：
     0    29k   58k   87k  116k  145k  174k  203k
0   [####################################] 前面的行要算很多列
29k      [###########################]     
58k           [###################]        中间的行
87k                [############]          
116k                    [######]           
145k                        [##]           
174k                         [#]           后面的行只算很少列
```

**解决方案**：
```python
# 1. 将矩阵分成小块
tasks = []
for i in range(0, N, 2048):
    for j in range(i_end, N, 2048):
        tasks.append((i, i_end, j, j_end))
# 共4950个任务块

# 2. 任务队列
task_queue = Queue()
for task in tasks:
    task_queue.put(task)

# 3. GPU动态取任务
while True:
    task = task_queue.get()  # 完成一个，立即取下一个
    if task is None: break
    process_task(task)
```

**效果**：
```
v9动态分配，完美均衡：
GPU 0: 670个任务, 25.40秒
GPU 1: 675个任务, 25.01秒
GPU 2: 766个任务, 25.01秒  ⬅️ 快的GPU自动多干
GPU 3: 681个任务, 25.01秒
GPU 4: 696个任务, 24.96秒
GPU 5: 815个任务, 24.93秒  ⬅️ 最快GPU干最多
GPU 6: 647个任务, 24.71秒

负载均衡度：97.3%
时间差距：仅0.69秒！
```
