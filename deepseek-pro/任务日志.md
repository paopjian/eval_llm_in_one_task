# 任务日志：大规模人脸特征相似度矩阵计算与评估

- **任务**：读取 `s4_0618_enhance.pkl`，计算 NxN 上三角相似度，区分正负样本，计算 TPIR@FPIR 指标，
  支持 above/below 阈值样本对提取，绘制相似度分布图与 TPIR@FPIR 曲线（中文字体），多卡并行加速。
- **环境**：`cvlface`（torch 2.12.0+cu126、numpy 2.2.6、matplotlib），
  7×NVIDIA RTX 4090（cuda:0–6），128 核 CPU，未安装任何新库。
- **数据**：N=203,234 样本（512 维 L2 归一化特征），9,940 个身份；
  总样本对 20,651,927,761（约 206.5 亿），正样本对 2,179,084（0.01%），负样本对 20,649,748,677。

### 关键设计
- **只算上三角**：行块 i 只与列块 j≥i 做 GEMM，对角线块仅取 `triu`，避免约 50% 冗余计算。
- **内存优化**：不物化 NxN 矩阵（约 165GB），分块流式计算，每卡峰值显存 < 3GB；
  相似度按 5e-5 分辨率量化到 40001 个 bin 的 int64 直方图，以 O(40001) 内存替代 206 亿浮点存储。
- **正负样本分离技巧**：负样本直方图 = 全体直方图 − 正样本直方图，热路径无需逐元素比对身份标签。
- **精度**：fp32 GEMM；TPIR 用排序后正样本精确计数（`searchsorted`），FPIR 用保守定义（≤目标）。

## 五、"单卡比多卡还快"的分析与优化（第二轮迭代）

### 5.1 初步结论：对比不公平 + 多卡实现有真实开销

最初日志中"单卡 4.66s vs 7 卡 7.12s"**不是公平对比**：step2 只做直方图+正样本，
step3 额外含样本对提取（0.63s）与绘图（1.58s）。同口径（core 模式）下多卡本来就更快，
但提速远小于 7 倍，逐一剖析后定位并消除了 5 个真实瓶颈：

| 瓶颈（实测证据） | 优化手段 | 效果 |
|------|------|------|
| ① 线程版 GIL：325 个小块 × ~5ms Python/算子调度被 7 线程串行化（壁钟比各线程 solo 之和多 ~1.8s） | 块大小 8192→16384，块数 325→91，调度开销摊销 4 倍 | 单块调度占比大幅下降 |
| ② 正样本 CPU 串行 1.0s 且持 GIL 干扰 GPU worker | GPU padded baddbmm 一次算完（9940×38×38 批 GEMM） | 1.0s → **0.04s** |
| ③ 量化链 int64 中间量 | torch 2.12 CUDA int32 bincount | bincount 2.3→1.7ms/67M |
| ④ 多卡并发传输 416MB/卡 争抢 PCIe 织物（6 卡共享 ~2.7GB/s 有效带宽，实测 0.91s；单卡直连仅 0.02s） | pinned 原位注册（cudaHostRegister）+ **流式按块异步传输 + 专用计算流**（避开 legacy 默认流的全流隐式同步），传输与计算完全重叠 | 传输成本融入计算窗口 |
| ⑤ CUDA 主上下文初始化被驱动全局锁串行化（7×~0.15s，发生在 worker 计时前，造成 ~1.2s 隐形壁钟） | 数据加载期间由辅助线程预初始化 7 个上下文，并行隐藏 | 直方图壁钟 2.27s → **1.06s** |
| ⑥ `below_pos_pairs.npz` zlib 压缩耗时 2.82s（785k 行） | 改无压缩 npz 保存 | 2.8s → 0.05s |

### 5.2 硬件事实（排除了环境因素）

- 7×RTX 4090 同时满载实测：每卡 450W、100% 利用率、1890-2085MHz 满频、温度 ≤63°C——**无供电/散热降频**；
- fp32 GEMM 实测 45-55 TFLOPS、TF32 68 TFLOPS——计算能力正常；
- 平台限制：6 张卡跨 NUMA/交换芯片共享传输织物（~2.7GB/s 汇总），2.5GB 特征数据搬运 ~0.9s 是物理下限（已与计算重叠）。

### 5.3 最终性能对比（同口径）

| 场景 | 单卡 | 7 卡 | 加速比 |
|------|------|------|--------|
| core：加载+正样本+直方图+指标 | 3.54s | 3.02s | 1.17× |
| └ 其中直方图 pass（206 亿对） | 2.51s | **1.12s** | **2.24×** |
| 完整流程（+提取+绘图） | ≈7.2s | **5.04s** | 1.43× |
| └ 其中样本对提取 | 1.67s | 0.39s | 4.3× |

参考基线：step2（单卡，无提取/绘图）4.66s；step3（7 卡线程版，完整）7.12s。
step4 v5 完整流程 5.04s，比 step3 快 1.41×，且比 step2 的"裸核心计算"只慢 0.4s（却多做了提取+绘图）。

### 5.4 为什么总时间没有接近 7 倍提速（诚实结论）

1. **传输织物是硬地板**：多卡必须把 416MB 特征搬到每张卡（2.9GB 总量），6 卡共享 ~2.7GB/s 跨节点带宽 → ~0.9s，单卡直连只需 0.02s。这是平台拓扑限制，不是代码问题（已用流式传输完全重叠隐藏）。
2. **固定成本不随卡数减少**：数据加载+pinned 注册 ~1.4s、绘图 ~1.5s、上下文初始化 ~1.2s（与加载并行）、指标计算等。
3. 直方图纯计算部分：单卡 2.2s → 7 卡 0.35s ≈ **6.3× 并行加速**，符合预期；提取 4.3×。
4. 结论：**多卡确实更快**（完整流程 1.43×，核心 1.17×，直方图 2.24×），此前"单卡更快"是口径不同 + 线程 GIL/上下文初始化等可修复开销造成的假象；在更大数据规模（样本对数更多）下固定成本占比下降，多卡优势会进一步扩大。
