```bash
# 1. 克隆或下载项目
```

## 🏆 性能测试结果

### 📊 统一再评估结果（2026-09-07，可复现）

> 全部模型在**统一评估框架**（`benchmark/`）下重新测试：数据读取、直方图网格（统一 200K bins）、
> 计数校验、TPIR@FPIR 指标、计时/超时/内存控制均为**同一份代码**，各模型只保留其**核心计算**
> （并行/分块/精度等差异，见 `benchmark/cores/`）。环境：7×RTX 4090；基准 = cluster_utils
> **get_sim_matrix_large_scale_v5**（v4 升级版：masked_fill+histc、neg=full−pos），同框架同口径。
> 规则：**200K 阶段 60s 超时筛选 → 合格者进入 2M 阶段（30min 超时 + 400GB 内存上限）**。
>
> ⚠️ 口径说明：本表"耗时"= 统一加载 + 核心计算 + 校验/指标，**不含绘图、样本对提取等外围流程**；
> 与 2026-09-06 旧数据（各模型完整程序口径，如 GLM 47s / Qwen 796s）不可直接比较，**旧结论已被本表取代**。
> 完整结果与逐模型校验记录：`03-统一基准测试报告/04-统一评估结果.md`、`benchmark/cores/VERIFICATION_NOTES.md`。

#### 💡 核心发现（重新评估后）

- 🚀 **2M 阶段冠军：GLM（36.4s，54.9 G对/s，基准的 0.76×）**；
  grok 以 7.9GB 峰值内存成为最省显存方案（2M 44.7s）。
- ⚡ **200K 阶段最快：grok（6.7s，基准 0.63×）**；
  除 claude-opus-m（5.00×）外，所有模型 200K 都快于基准。
- 📈 统一框架下 11 个模型在 2M 全部通过严格计数校验，且 TPIR@FPIR 互相吻合
  （FPIR=1e-5 阈值 0.18709–0.18714、TPIR≈0.001%，fp16/tf32 方法仅有 ≤5 bin 量化差）
  ——各实现被交叉验证一致；TPIR 绝对值极小源于 200w 合成数据同身份相似度≈随机对，
  该指标在此仅用于验证正确性。
- ⚖️ **基准已升级为 cluster_utils v5**：2M 47.9s / 41.8 G对/s（比 v4 的 81.4s 快 1.7×，200K 基本持平）；
  在此新基准下，claude-opus（54.6s，1.14×）与 qwen（75.6s，1.58×）在 2M 已**慢于基准**。
- 🔧 旧口径的"失败模型"在统一框架下 4/5 复测通过（deepseek、deepseek-pro、codex-sol-m、
  claude-opus 的原失败均源于各自完整程序中的加载/绘图/提取/内存缺陷，不再计入核心耗时）；
  glm-pro 因核心本身的正样本 gather 越界（CUDA 崩溃）仍失败；claude-opus-m 2M 超时
  （CPU 分桶设计无法扩展）。
