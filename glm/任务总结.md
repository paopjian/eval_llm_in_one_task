## 4. 核心设计方案

### 4.1 用统计代替全量保存（关键决策）
- 相似度**不在显存/内存/磁盘中保留**：GPU 端对每个 tile 实时 `torch.histc` 统计进 2,000,000 bins 直方图（bin 宽 1e-6）。
- 拆分统计：`负样本直方图 = 全体直方图 − 正样本直方图`（同一直方图网格上严格成立），避免对每对做正负判断后分开统计的开销。
- 主进程合并 7 卡直方图后即得完整负样本分布；结果持久化为 `neg_hist.npy`（16MB）+ `pos_sims.npy`（8.3MB），**后续任何阈值分析无需重算**。

### 4.2 TPIR 精确、FPIR 高分辨率近似
- **TPIR 精确**：正样本相似度全量收集（218 万条 fp32），`searchsorted` 直接得分位数，无直方图误差。
- **FPIR 高分辨率**：由负样本直方图尾部累计计数 `S[i] = Σ_{j≥i} counts[j]` 反解阈值：找最小的 j 使 `S[j] ≤ ⌈FPIR·N_neg⌉`，阈值取该 bin 左边缘。
- **交叉验证**：提取模式二次扫描的精确计数反推 FPIR=1.000e-3，与直方图阈值设定完全吻合。

### 4.3 计算精度
- **fp32 矩阵乘 + 关闭 TF32**：微基准显示 matmul 仅 6.3ms/tile（91 个 tile），计算完全不是瓶颈，因此无需牺牲精度换 fp16/bf16 速度，相似度误差 ~1e-6 量级。
- 特征加载后兜底重新 L2 归一化，保证 `sim = A@Aᵀ` 严格成立。

### 4.4 多卡并行与内存控制
- **分块上三角**：`block=16384`，91 个 tile，对角 tile 只统计严格上三角（排除自身对），下三角填范围外值让 `histc` 自动丢弃，避免额外拷贝。
- **进程级并行**：每 GPU 一个 spawn 进程，特征通过共享内存只传一份，各卡常驻 416MB fp32。
- **动态负载均衡**：tile 入共享任务队列（宽 tile 优先），先启动的卡多做，天然消除卡间速度差。
- 显存峰值 ~1.4GB/卡（tile 1GB + 特征 0.4GB），单卡即可跑，`--gpus 0` 可降级。

### 4.5 样本对提取（错误分析）
- 二次扫描模式：worker 只回传全局索引 `(i, j, sim)`（避免大体积传输），主进程统一映射回 id 与文件路径。
- **精确计数 + top-K 保存**：每个阈值输出真实命中总数（可反推 FPIR/TPIR），CSV 按相似度降序保存 top-K 条。
- 三种指定方式：`--extract-fpir`（阈值之上负样本对 = 错误接受）、`--extract-tpir`（阈值之下正样本对 = 错误拒绝）、`--extract-thresh`（原始阈值，两者都出）。

## 5. 性能实测

| 阶段 | 耗时 |
|---|---|
| pkl 加载（440MB） | 0.6s |
| GPU 扫描（7 卡，含进程启动/CUDA 初始化） | 5.2s |
| 其中纯 GPU 计算（matmul + histc，91 tiles） | ~1.6s（单卡合计） |
| 指标计算 + 绘图 + 落盘 | ~3s |
| **总计** | **9.5s** |

- 单 tile 实测：matmul 6.3ms + histc 4.4ms（B=16384）
- 说明：N=20 万规模下进程启动占大头，7 卡与单卡总耗时接近（8.6s vs 9.5s）；GPU 纯计算部分 7 卡加速约 7 倍，数据规模继续增大（或 block 增大减少 tile 数）时多卡收益线性显现。
- 单卡与 7 卡结果完全一致（交叉验证了并行合并逻辑）。

## 7. 使用方法

```bash
# 基础流程：统计 + TPIR@FPIR + 绘图（~10s）
./run.sh eval_similar.py

# 提取 FPIR=1e-3 与 1e-4 阈值之上的负样本对（错误接受分析）
./run.sh eval_similar.py --extract-fpir 1e-3,1e-4

# 提取 TPIR=0.95 阈值之下的正样本对（错误拒绝分析）
./run.sh eval_similar.py --extract-tpir 0.95 --extract-max 50000

# 按原始阈值同时提取 above/below
./run.sh eval_similar.py --extract-thresh 0.5

# 指定 GPU / 分块 / 直方图精度
./run.sh eval_similar.py --gpus 0,1,2 --block 16384 --bins 2000000
```

主要参数：

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--gpus` | 0,1,2,3,4,5,6 | 参与计算的 GPU 列表 |
| `--block` | 16384 | 相似度分块大小（显存 ~1.4GB/卡） |
| `--bins` | 2000000 | 相似度直方图 bin 数（阈值分辨率 2e-6） |
| `--extract-fpir` | 无 | 逗号分隔 FPIR 值，提取其阈值之上负样本对 |
| `--extract-tpir` | 无 | 逗号分隔 TPIR 值，提取其阈值之下正样本对 |
| `--extract-thresh` | 无 | 逗号分隔原始阈值，同时提取 above/below |
| `--extract-max` | 100000 | 每个阈值最多保存的样本对数（计数不受限） |

## 8. 演进过程回顾

1. **v1 数据探查**（`test_load_data.py`）：确认数据格式、归一化、正负样本对规模 —— 由此发现"206.5 亿对不可全量存储"这一核心约束。
2. **GPU 微基准**：实测 matmul 6.3ms、histc 4.4ms/tile → 确认计算不是瓶颈，选型 fp32 精确计算 + 直方图统计；确定 block=16384（显存 1.4GB 安全）。
3. **v2 完整系统**（`eval_similar.py`）：分块上三角 + GPU 直方图 + 精确正样本收集 + 多卡队列调度 + TPIR@FPIR + 绘图 + 提取模式，一次运行全部落在预期范围。
4. **迭代修正**：对角 tile 的 clamp 顺序（下三角填充值会被 clamp 回直方图范围内污染计数）、`extract_max` 未传入 worker、totals 解包错误、绘图零计数基线误导、阈值面板 -1 下坠等，均在验证中定位并修复。
