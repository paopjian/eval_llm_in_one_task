## 📈 性能分析〔09-06 旧口径方法消融分析,该口径结论已删除/被 04-统一评估结果 取代,仅供追溯〕

> 权威口径:200K 阶段最快 grok 6.663s;2M 阶段最快 glm 36.444s;13 项两阶段表见 `03-统一基准测试报告/04-统一评估结果.md`。

### 1. 为什么hybrid_optimal最快？

**技术组合**:
```
ThreadPoolExecutor (省27秒启动)
+ TF32精度 (核心计算快5倍)
+ 对数切分负载均衡 (88%均衡度)
+ 200K bins (高精度)
= 0.348秒总耗时 ⚡⚡⚡
```

**与grok对比**:
- grok使用FP32，核心计算0.851秒
- hybrid使用TF32，核心计算0.170秒
- **TF32加速: 5.0×**

### 2. 为什么Spawn方法这么慢？

**时间分解** (以codex_tf32为例):
```
总耗时: 27.472秒
├─ 数据加载: 0.615秒 (2.2%)
├─ 核心计算: 0.448秒 (1.6%)
└─ 进程启动: 27.024秒 (96.2%) ← 瓶颈！
```

**Spawn启动开销包括**:
- 7个独立进程启动
- 每个进程的CUDA初始化
- 数据序列化和传输
- 进程间通信建立

### 3. TF32 vs FP32精度对比

**核心计算时间**:
- hybrid_optimal (TF32, 200K bins): 0.170秒
- codex_tf32 (TF32, 200K bins, Spawn): 0.448秒
- grok_threadpool (FP32, 100K bins): 0.851秒
- deepseek_precise (FP32, 200K bins): 0.444秒

**TF32优势**:
- 在ThreadPool模式下: 5.0× 加速（0.170秒 vs 0.851秒）
- 在Spawn模式下: 与FP32相当（被启动开销掩盖）

**精度对比** (TPIR@FPIR=1e-5):
- 所有方法: 63.95-63.96%
- **精度差异: <0.01%** (可忽略)

### 4. Bins数量影响

| Method | Bins | 核心计算 | 影响 |
|--------|------|---------|------|
| grok | 100K | 0.851秒 | 基准 |
| codex/deepseek | 200K | 0.444-0.448秒 | 相当 |
| glm | 2M | 0.477秒 | 轻微增加 |

**结论**: Bins从100K→2M，性能影响<12%
